# Risk Assessment

## S.U.P.E.R Architecture Health Summary

| Area | Health | Hotspots |
|:-----|:------:|:---------|
| Single-purpose | 🟡 | Auth subsystem framework-bound inside web app (biggest S violation); `proxy.ts` mixes guard + locale |
| Unidirectional flow | 🟢 | Clean `pages → lib → api facade → Go` one-way graph; no cycles |
| Ports over implementation | 🟡 | Contracts duplicated between `packages/shared` and `lib/*`; a few pages bypass facades |
| Environment-agnostic | 🔴 | **Dockerfile layout coupling** (static assets COPY'd to wrong standalone paths) — live incident |
| Replaceable parts | 🟡 | Route/UI replacement coupled to Next (8-10 router call sites); Store interface in Go is replaceable |

**Priority targets for the plan**: (1) fix the deployment layout class of failure by removing Next from the runtime; (2) extract auth from the framework into the Go subsystem; (3) keep contract sync between `packages/shared` and TS/Go.

## Risk Register

### R1 — Auth migration fidelity (Critical, High probability)
- **What**: 12 Next auth routes → Go: email/password (bcrypt), email verification, GitHub/Google OAuth callbacks, TOTP 2FA + recovery codes, WebAuthn passkeys, session cookie rotation.
- **Impact**: Broken logins/lock-outs/users cannot register in live mode (demo mode unaffected — not used today, but must not regress once auth ships).
- **Mitigation**:
  - Go equivalents exist for every primitive with drop-in semantics: `x/crypto/bcrypt` (same hash format — existing DB rows stay valid), `github.com/pquerna/otp` (TOTP + recovery code gen), `github.com/go-webauthn/webauthn` (verify/register), stdlib `net/http` + `golang.org/x/oauth2` for GitHub/Google.
  - Port the 6-table schema 1:1 (same column names/types) so an existing SQLite file mounts unchanged.
  - Extract per-route Go tests mirroring the existing zod validation: register/login/2FA/WebAuthn/verify flows.
  - Keep the client API surface byte-identical: same paths `/api/auth/*`, same JSON fields, same cookie name `diffaudit_session` (HttpOnly, SameSite=Lax, Secure in prod).
  - **Defer acceptable**: the frontend SPA can ship demo-mode-first; auth routes land server-side without UI changes.

### R2 — SPA vs SSR behavioral differences (High, Medium probability)
- **What**: Current marketing pages are SSR'd (`next/font`, `metadata`, `robots.ts`, `sitemap.ts`, JSON-LD, og images, `docs` pages). SPA client-renders.
- **Impact**: SEO (og:title preview, robots/sitemap, crawler indexing) degrades; `next/headers` locale detection source changes.
- **Mitigation**:
  - Static fallback via `vite-plugin-html` or per-route `index.html` metadata for marketing pages; `robots.txt` + `sitemap.xml` as static files; og images already static in `/brand/`.
  - Locale: read from cookie in SPA (same `platform-locale-v2` cookie, same `x-platform-locale` behavior server-side).
  - Fonts: Inter via `@fontsource/inter` local package — removes `next/font/google` network/self-hosting complexity.
  - Accept SSR loss as product-level tradeoff for marketing pages; verify with a crawler smoke test in e2e.

### R3 — Route/URL parity (High, Medium probability)
- **What**: 20 routes incl. `redirectTo` semantics, 404 page, login redirect, docs `[...slug]` dynamic segment, legacy route redirects (`legacy-routes.ts`).
- **Impact**: Broken deep links, inconsistent auth redirects, 404 UX.
- **Mitigation**:
  - React Router v7 (library mode) with a route table mirroring current paths + `redirectTo` query handling preserved.
  - Port `legacy-routes.ts` table to the router (already a declarative map — low risk).
  - Keep `/health` and `/api/*` untouched server-side.

### R4 — Demo-mode behavior contract (Medium, High probability)
- **What**: `proxy.ts` gates demo mode via `DIFFAUDIT_DEMO_MODE` env + `platform-demo-mode` cookie; demo API routes serve hardcoded payloads; Nuance: direct client import of `demo-snapshot.ts` changes where data "lives" (no network round trip).
- **Impact**: Demo pages may render from different code paths than before (still same view models), and `workspace-source.ts` mode detection must stay consistent.
- **Mitigation**:
  - Keep `workspace-source.ts` as the sole mode selector; demo modules are already the imported data source used by pages.
  - Add a vitest contract test: demo mode payload generated by `demo-jobs-store` output equals previous route JSON shape (snapshot test).
  - Optional: Go serves `/api/demo/*` for parity (keeps network path identical) — decide at Phase 3; client import is the default to keep scope tight.

### R5 — E2E retarget (Medium, Low probability)
- **What**: Playwright `webServer` currently boots `next dev/start`; Vitest may rely on Next test utils (route handler tests).
- **Impact**: CI blocks on test infrastructure, not product regressions.
- **Mitigation**: retarget to `vite preview`; component tests already use plain React + testing-library (no Next-specific runner); route-handler tests move to Go integration tests.

### R6 — Deploy swap and rollback (Low, Medium probability)
- **What**: New single-binary container replaces the merged Next+Go one; DNS/Tunnel layer unchanged; demo data volume must survive.
- **Impact**: Brief downtime or wrong static paths if the SPA dist is served incorrectly (repeat of the current incident).
- **Mitigation**:
  - Serve static via `embed.FS` with SPA fallback routing (index.html for unknown paths → 404 only under `/api/*`).
  - Keep the same ports/env contract (`DIFFAUDIT_API_BASE_URL` no longer needed; gateway self-serves; `DIFFAUDIT_PUBLIC_DATA_DIR` unchanged).
  - Rollback plan: previous image tag stays published (immutable tags already), redeploy is one tag revert.
  - Smoke after swap via e2e `smoke.spec.ts` against the running container.

### R7 — Public repo boundaries (Low, High probability)
- **What**: `scripts/check_public_boundary.py` (13 categories) gates every commit; planning docs live in `.agents/planning/` inside a public repo.
- **Impact**: Wasted rework if docs leak hostnames/paths/secrets; CI red.
- **Mitigation**: planning docs use only product-level identifiers (verified drafts); run `check:public` before any push; no infra topology anywhere in this repo.

### R8 — Contract drift between TS/Go/packages-shared (Medium, High probability)
- **What**: three copies of payload shapes (zod in web, structs in Go, docs in packages/shared).
- **Impact**: subtle field mismatch between front-end and Go after migration.
- **Mitigation**: keep `packages/shared/contracts/` as authority; Go structs and zod schemas generated or test-enforced against the same example payloads in Phase 3.

## Complexity Hotspots (planning targets)

1. `apps/web/src/app/api/auth/*` (12 routes) — biggest rewrite block: 1.5k LOC, 4 external protocols (OAuth x2, WebAuthn, TOTP).
2. `apps/web/src/app/(workspace)/**` — 14 pages, largest component cluster; mechanical router work, not logic.
3. Docker/build chain — root cause of the live incident; full rebuild of the build stage (remove node runtime) deletes the failure class.
4. Contract sync — cross-cutting; introduce a contract test (payload fixture → both parsers) to lock parity.
